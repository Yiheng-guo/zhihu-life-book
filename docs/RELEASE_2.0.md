# 2.0 · 你的下一页

从“读几页资料”升级为场景选择、真实经历、知乎 AI 回应、带回今天的完整体验。

## 用户体验

- 四阶段条件分支保留，短标题与得到/付出帮助用户快速做决定。
- 封面与正文统一为人生路径；微粒在决定时收束，分岔线随焦点延伸；声音默认关闭，可主动开启；系统减少动态效果偏好会关闭视差与持续动画。
- 知乎来源可单选，长摘要折叠，原文独立打开；手机用横向卡片减少纵向阅读。
- 选中来源后使用“经历向导”：自由提问、帮我拆小步、找相似经历。回答可追问，能主动采纳到结尾书签。
- 八种毕业情境全部可读；历史只回顾用户实际选过的行动，不给人生打分。

## 真正上线的 AI

一个来源向导，由服务端控制检索工具与输出校验。普通提问读取当前来源并调用知乎直答 `zhida-fast-1p5`；请求更多经历时先调用知乎搜索。会话历史由共享状态机重放，来源 ID 和 URL 均校验。生成只丰富解读与今日行动，不预测人生，也不替用户选择结局。

返回：回应顾虑、一个小步、一个澄清问题、知乎引用。第二次追问只带入服务端已验证的上一轮对话。页面区分实时、缓存和预整理降级。

## 架构与团队接手

浏览器以共享状态机即时推进 → 同源 Worker `/api/guide` → 知乎搜索/直答。D1 保存短期缓存、去重锁与额度计数。服务器凭证不进入前端或仓库。用户问题发送前有提示；缓存与对话保留 2 小时有效期，过期数据每小时清理一次。

- `frontend/app.mjs`：场景、来源、向导与书签交互。
- `frontend/styles.css`、`experience.mjs`、`cover.mjs`：页面、轻粒子、音效与转场。
- `frontend/story.mjs`、`branches.mjs`：四阶段条件分支和合法事件。
- `backend/guide.mjs`：检索、直答、对话、验证、缓存与限制。
- `backend/worker.mjs`：公网同源服务；`server.mjs`：本地联调。
- `db/schema.ts`、`drizzle/`：缓存与限额表；生成迁移随部署应用。

## 额度与响应边界

使用知乎开放平台 Access Secret，不使用个人 OpenAI API Key；不能把知乎直答次数等同“500 美元模型资源”。每会话 2 次生成、每 IP 每日 8 次、全站每日最多 50 次生成尝试；重复缓存不重复调用。`GUIDE_DAY_LIMIT=0` 可关闭新生成。搜索最多等待 3 秒，总请求 11 秒，到时显示诚实降级且不阻塞继续阅读。

当前 7 条人工整理来源是基本资料；按需搜索可新增引用。没有实现知乎 OAuth、站内发帖、用户账户和跨设备进度；这些不是当前体验的前置条件。

## 路演（3 分钟）

0:00–0:20：高考遗憾入口，解释“过去已成章节，今天仍可落笔”。
0:20–0:50：一次选择，看到明确的得到/付出；点选一条知乎经历，展示独立原文。
0:50–1:25：向 AI 提问现实顾虑，得到带引用的小步；点“带回今天”。
1:25–2:10：下一阶段出现源自所选经历的新行动，继续到毕业，展开不同人生可能。
2:10–2:45：回顾四次选择，看到 AI 小步保留在今日书签，修改并带走。
2:45–3:00：一句落点：“我们想改变的，是把现在的自己判为失败，变成今天可以请教和尝试的具体问题。”
