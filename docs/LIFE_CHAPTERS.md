# 人生之书：全生命周期章节架构

## 1. 全书模型

“人生之书”是一套由真实问题、扎实回答和持续启发组成的互动叙事系统。人生不是一条预设的成功路线，而是由多个阶段、许多次选择和不断回看的经验组成。产品把每个人生阶段做成一章：用户先进入一个具体处境，再做出选择，随后看到不同路径的剧情反馈，并可以阅读多条知乎真实经历，继续追问、比较或重新选择。

每章都遵循同一条体验链：

```text
阶段引子 → 当前处境 → 用户选择 → 多条真实经历 → 下一步行动/继续探索 → 阶段性结局
```

章节之间既可以按时间顺序串联，也允许用户从目录回看已经完成的章节。章节结局不是给人生下定论，而是把“一事无成”“来不及了”等沉重判断拆成可了解、可请教、可尝试的问题。

## 2. 统一章节数据结构

所有章节使用相同的结构，便于后端编排、前端渲染和未来扩展：

```json
{
  "chapter_id": "university",
  "title": "大学篇",
  "stage": "18-22岁",
  "order": 1,
  "cover": {"image": "...", "mood": "回望与选择"},
  "opening": {"hook": "阶段引子", "question": "此刻真正困扰你的问题是什么？"},
  "nodes": [
    {
      "node_id": "freshman_start",
      "situation": "当前处境描述",
      "narration": "剧情文本",
      "choices": [
        {"id": "choice_a", "label": "选项 A", "next_node_id": "..."}
      ],
      "experiences": [
        {
          "source_id": "zhihu-answer-...",
          "title": "知乎经历标题",
          "summary": "基于原文的短摘要",
          "url": "https://www.zhihu.com/...",
          "source_type": "answer",
          "verified_at": "YYYY-MM-DD"
        }
      ],
      "next_action": "用户可以尝试的一步"
    }
  ],
  "endings": [{"ending_id": "...", "label": "阶段性结局", "next_chapter_id": "..."}]
}
```

字段约定：`chapter_id` 与 `node_id` 稳定且唯一；`choices` 只描述允许的路径；`experiences` 是可选的多条来源卡片，不限制为一条；`next_chapter_id` 用于章节之间的扩展。AI 可以改写叙事语气和摘要，但不能凭空增加节点、选择或来源。

## 3. 大学篇：第一章

大学篇是比赛阶段的首章，用来验证“选择—真实经验—继续探索”的核心机制。它从“未能珍惜年少考入好大学，以致此生碌碌无为”的人生遗憾引子开始，覆盖入学、学习与社团、考研/考公、校招、Gap Year、迷茫与毕业等关键节点。

大学篇需要支持开放式结局：用户可能考入理想院校、考研、考公、参加工作、选择 Gap Year、享受生活、仍然迷茫、找不到工作，甚至留级。系统不把任何结果标成唯一正确答案，而是在结尾展示“你走到这里的路径”、可继续了解的真实经历和下一章入口。

## 4. 后续章节扩展

后续章节只需新增同样结构的数据和内容，不改前端主流程：

| 章节 | 典型处境 | 可延展的选择 |
| --- | --- | --- |
| 恋爱篇 | 相遇、关系、分开与独处 | 进入关系、沟通、结束、重新认识自己 |
| 工作篇 | 求职、转行、职业倦怠 | 入职、转行、创业、暂停或继续积累 |
| 家庭篇 | 婚姻、生育、照护与责任 | 组建家庭、不婚、育儿、照护父母 |
| 晚年篇 | 回望、健康、关系与遗憾 | 重新连接、学习、旅行、留下经验 |

章节之间通过 `next_chapter_id` 和用户已完成的节点连接。每一章可以独立体验，也可以沿着用户的时间线连续阅读；后续不要求一次性完成整个人生。

## 5. 留存机制

留存来自持续的“回来看一眼”和“再走一条路”，而不是强制打卡：

- **章节目录**：大学篇完成后解锁下一章预告，保留未探索章节。
- **多路径回看**：记录用户走过的节点，允许从分岔处重新体验。
- **经历收藏**：用户可收藏某条知乎经历，稍后继续阅读或请教。
- **问题清单**：把每次选择转成可带走的问题，例如“毕业后找不到工作，下一步可以了解什么”。
- **回访提示**：在有新内容、相似经历或下一章节开放时再提醒，避免无意义的频繁通知。

## 6. 来源溯源与内容边界

知乎经历是产品可信度的核心，每条展示内容必须保留 `source_id`、标题、原文链接、来源类型和核验日期。用户应能从经历卡片直达原始知乎页面；摘要和 AI 反馈要明确标注为整理内容，不冒充原作者原话。

内容处理遵循四条原则：

1. 一条选择可展示多条经历，让用户比较不同结果，不把单一故事当成规律。
2. 只使用已核验、可访问的公开来源；来源失效时显示降级提示，不编造替代链接。
3. AI 只能在已提供的节点和来源范围内组织表达，并保留引用关系。
4. 对敏感人生经历使用克制、非评判的语言，不把收入、学历、婚育或单一结果作为成功标准。
