# 版本管理规则

项目使用三段式版本号 `MAJOR.MINOR.PATCH`，对外简写为 `MAJOR.MINOR`：

- **大版本**：`1.0 → 2.0`。产品核心架构、主要叙事模型或比赛阶段发生重大变化。
- **小版本**：`1.0 → 1.1 → 1.2`。新增一个完整体验、章节、重要交互或可见能力。
- **修订版本**：`1.0.0 → 1.0.1`。修复问题、调整文案、补充来源或不改变产品结构的小改动。

## 每次迭代必须留下的记录

1. 更新根目录 `VERSION`。
2. 在 `CHANGELOG.md` 增加版本、日期、变更和验证结果。
3. 创建 Git tag，例如 `v1.0.0`、`v1.1.0`。
4. 推送 `main` 和 `develop`，并为重要版本创建 GitHub Release。
5. 若前端或部署内容变化，重新发布公网 Demo，并在变更记录中写明验证状态。

## 当前基线

`1.0.0` 代表第一版可体验基线：人生遗憾开场、大学篇选择、三条知乎来源、多种发散结局和公网 Demo。
