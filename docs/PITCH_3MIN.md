# 3 分钟评委理解路径

比赛的核心不是让评委把完整大学篇玩完，而是在 180 秒内证明四件事：故事抓人、互动清楚、知乎内容有价值、结局和行动形成闭环。

| 时间 | 评委应看到 | 讲述重点 |
|---|---|---|
| 0:00–0:20 | 开场遗憾问题 | 过去的一个结果，为什么会变成对整个人生的解释？ |
| 0:20–0:55 | 入学选择 + 两条机会/代价 | 用户不是点下一页，而是在权衡一次真实选择。 |
| 0:55–1:25 | 3 条知乎来源，选中 1 条，独立打开原文 | 知乎不是装饰；内容带来一个可追问的问题。 |
| 1:25–1:55 | 探索或大三准备的下一次选择 | 上页问题被带进下一页，故事有记忆、有承接。 |
| 1:55–2:30 | 毕业分叉与至少 4 种情境 | 读研、工作、考公、Gap Year、迷茫、暂未就业、延后毕业不是排名。 |
| 2:30–2:50 | 回望路径 + 今天的一步 | 沉重判断被改写成可以尝试的问题和行动。 |
| 2:50–3:00 | 收束产品价值 | 借助知乎真实内容，让人与人的经历继续产生启发。 |

## 现场操作约束

- 预先打开封面，不现场等待网络或模型。
- 只现场操作两次剧情选择和一次来源选择；其余节点用明确的已完成状态展示。
- 不承诺“全站最高赞”或“这个选择会导致某种结果”；只说这是创作起点与产品编排。
- 先讲故事和交互，再讲技术：静态公网版、同源 API、来源字段、未来内容助手。
