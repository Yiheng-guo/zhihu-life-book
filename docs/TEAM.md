# 团队分工与协作流程

## 四个责任区

### 队长：产品、比赛表达与验收
- 守住“人生之书·大学篇”的定位、范围和 P0 闭环。
- 统筹剧情、前端、后端、知乎内容，确认现场 Demo 和提交材料。
- 负责最终体验验收、路演叙事、README 与演示视频协调。

### 谭一凡 + 王涵硕：前端、交互与视觉
- 谭一凡：前端工程、页面实现、状态管理、接口接入。
- 王涵硕：交互流程、书籍视觉、素材、动画和页面节奏。
- 共同交付：开场 → 进入故事 → 一次选择 → 反馈 → 下一节点。

### 林博：工程基础设施与发布
- GitHub 协作、开发环境、依赖、配置、部署和线上 Demo。
- 处理构建、运行、合并冲突和发布稳定性。
- 不承担故事 API 的主要开发责任。

### 徐闻阳：后端故事 API、知乎内容与 AI 编排
- 剧情节点、用户选择和会话状态。
- 后端 API、知乎搜索/知识库内容筛选、AI 分步反馈。
- 保管服务端密钥，负责和前端完成接口联调。

## 分支流程

- `main`：可演示、可提交的稳定版本。
- `develop`：团队集成分支，用于合并已完成功能和联调。
- `feature/<name>`：个人功能分支，例如 `feature/story-api`。

个人完成后推送功能分支并发起 Pull Request 到 `develop`。联调通过后由队长合并；阶段稳定版本再从 `develop` 合并到 `main`。

## 提交规则

提交信息使用 `type: description`，例如：

- `feat: add story choice endpoint`
- `fix: handle empty references`
- `docs: update api contract`

不要提交 `.env`、Access Secret、模型密钥、钥匙串导出、个人缓存或大体积未授权素材。
