# 人生之书 2.1：行动、时间与真实来源

2.0 的主线固定使用 7 条预整理来源；运行时搜索只进入可选 AI 问答。2.1 把搜索接入每次确认行动之后，搜索结果成为可以采纳、带入下一节点、写进书签的来源。

## 用户流程

1. 选择本次关心的方向、时间或生活开支。
2. 每幕先选一个短行动，才展示该行动的得失。前三幕可以分配 1–3 个课余时段；时段是情境设定，不是录取概率或人生分数。
3. 确认后立即进入来源卡；知乎检索在后台运行。已有卡片可以阅读，迟到或用户正在操作时的新结果由用户主动打开，不替换正在读的内容。
4. 每次只展示一条短摘要。可以换人、独立查看原文、换检索角度，或借其启发继续。下一幕保留同一个来源启发行动。选择该行动才实际执行，不把阅读误写为用户完成项目。
5. AI 收到当前路径、来源与用户问题；复用已检索快照，通常仅把最相关的 3 条来源交给模型，缩短响应。AI 展开后才出现；流式阶段只报进度，最终引用 ID 校验通过才显示正文并允许采纳。
6. 毕业探索 8 种可能处境，结尾写一个今天能做的小步，下载带真实来源链接的书签。毕业处境不记录虚构的时间投入。

## 技术接入

浏览器：原生模块、共享状态机、单张来源卡、原生 range 与时间按钮、AbortController。Node 本地与公网均使用浏览器状态机，旧 `/api/story/*` 留给基础规则联调。

服务端：Cloudflare Worker，同源 `/api/guide/session`、`/api/guide/sources`、`/api/guide`。D1 保存 2 小时查询缓存、会话绑定来源快照、预算计数、最近一轮已核验问答。快照按会话、路径、选择、投入量与查询复用；服务端重放时重新核验，不接受客户端伪造的来源正文。现有 D1 表足够，无新迁移。

上游仅使用 developer.zhihu.com 的知乎搜索与 `zhida-fast-1p5`。凭据仍在服务端，未接个人 OpenAI API key。知乎搜索接口额度与活动模型金额不是同一种额度；本页无法核验活动后台美元归账。

每次搜索最多请求 10 条，按 URL 去重，过滤明显推广与不相关结果；默认优先相关标题和有具体自述的摘要。不同操作、顾虑与检索角度改变查询；相同查询可命中缓存。没有声称穷尽知乎内容，也不保证每次换组都不重复。保留 7 条预整理来源作为离线回退。

限额：新检索 12 次/会话、32 次/IP/日、300 次/站点/日；快照 40 组/会话；AI 新回答 2 次/会话、8 次/IP/日、50 次/站点/日。额度用完仍能完成故事，明确显示回退状态。取消流会中止上游；收到 SSE DONE 立即完成，不继续等连接关闭。

## 验证记录

- 25 项离线测试通过：分支、8 种结局、动态来源重放、快照跨会话/路径/投入校验、缓存、额度、SSE 分块中文/结束/错误、取消传播。
- Chrome 在 1440 和 390 宽度走完四幕、分配时间、换人、打开原文、书签下载、重开；无页面异常或横向溢出。模拟迟到检索确认不会覆盖正在查看的卡片，采纳的新来源改变下一幕可选行动。
- 本地真实接口两条四幕路线：8 次检索取得 65 个去重 URL，各组 5–10 条；端到端检索约 0.7–1.0 秒（含测试等待150ms）。随后进一步收紧了项目类来源的校园语境过滤。
- 本地完整 AI 回答实测约 4.4 秒、3.4 秒、3.5 秒。属于少量样本，不构成所有用户都在 3 秒内完成的承诺。公网复核另记发布验收。

## 三分钟演示

0:00–0:25 从高考遗憾进入：已写下的分数，不能写完人生。
0:25–1:05 选择行动并投入时间，展示相应得失；换两张不同知乎来源，点开出处。
1:05–1:50 采纳一个启发，下一幕出现对应行动；说明每次检索由行动与现实顾虑决定。
1:50–2:25 在可选向导问一句真实顾虑，展示短回答与引用；继续剧情无需等待。
2:25–3:00 探索毕业处境，落到今天的小步并下载书签。

仍需改进：来源分类和推广过滤是规则启发式，摘要有局限；剧情骨架与来源启发行动由团队设计，并非无限生成的人生模拟器。接下来应通过真实用户试玩验证理解程度与复玩意愿。
