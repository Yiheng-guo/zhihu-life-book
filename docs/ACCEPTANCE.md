# P0 验收清单

## 产品体验

- [ ] 首屏 10 秒内说明“人生之书”是什么。
- [ ] 3–5 分钟内可完成一次选择和下一节点体验。
- [ ] 至少有两个选项，选择会造成可见的反馈差异。
- [ ] 至少展示一条可核验的知乎来源，包含标题和链接。
- [ ] 大学篇结尾明确“这是第一章”，并保留后续章节钩子。
- [ ] 加载、空结果、接口失败和额度耗尽都有用户可理解的降级提示。

## 技术与安全

- [ ] 前端不包含 Access Secret、App Key、OAuth Token 或模型密钥。
- [ ] 知乎和 AI 调用由后端完成，凭证来自环境变量或安全凭证系统。
- [ ] 热榜、搜索、直答和故事/知识内容请求有缓存或去重策略。
- [ ] `GET /healthz` 可验证服务存活。
- [ ] `POST /api/story/start` 与 `POST /api/story/choose` 可实际调用。
- [ ] API 返回结构稳定，错误包含 `code` 和 `message`。

## 比赛交付

- [ ] Demo 可从公网访问并完成核心流程。
- [ ] 产品说明/计划书包含核心思路、目标用户、核心体验、技术方案、知乎能力、生态契合和用户价值。
- [ ] 项目名称、主题/赛道、介绍、封面和 icon 已填写。
- [ ] GitHub 仓库可访问，README 有启动说明。
- [ ] 演示视频（如提交）可访问。
- [ ] 线上页面、API、登录流程（如使用 OAuth）经过真实验证。

## 决赛 3 分钟节奏

- [ ] 现场点击次数控制在 2 次，完成 4–5 个画面状态。
- [ ] 首次点击后出现多条知乎经历卡片，用户可在页面内选中一条。
- [ ] 原文溯源链接与“继续下一页”分离，不因点击来源离开 Demo。
- [ ] 结尾展示至少 4 种不同人生方向，并说明这是开放式可能而非结果预测。
- [ ] 总流程可在 3 分钟内稳定复现。
