# 比赛规则与策略记录

## 已核实规则

- 活动：`zhihu_hackathon_2026_p2`。
- 组队规模：2–5 人，每队一份作品，队长负责维护队伍和最终提交。
- 作品提交窗口：2026-09-13 10:00 至 2026-09-15 10:00；截止后不接受补交。
- 必交：公网可访问且可实际操作的线上 Demo、产品说明或计划书。
- 选交加分：GitHub/Gitee 仓库、演示视频。
- 可用知乎能力：知乎搜索、全网搜索、热榜、直答、用户数据；另有黑客松故事与知识内容接口。
- 有额度的调用需要缓存和请求去重；禁止批量、高频、无意义调用。
- 所有 App Key、Access Secret、OAuth Token 和模型密钥只放后端或安全凭证系统。

## 评分策略

当前已读取的官方参赛资料没有列出可验证的分项权重或“AI 占比”。因此本仓库不把任何未经官方页面确认的百分比当作规则。

在权重未核实前，按以下可审查目标推进：

1. **知乎生态契合**：真实问题、扎实回答、人与人之间持续启发。
2. **可操作体验**：评委无需听长篇说明即可完成核心流程。
3. **内容可信**：真实知乎来源可追溯，AI 不替代来源。
4. **新颖表达**：把人生经历做成可进入、可选择、可继续阅读的章节。
5. **留存理由**：大学篇只是第一章，用户有继续探索下一章和查看他人经历的动机。
6. **技术可靠**：公网 Demo 稳定，失败和空数据有降级路径，凭证不泄露。

若活动页面或官方答疑出现明确评分表，应以最新官方信息更新本文件，并据此重新排序开发优先级。
